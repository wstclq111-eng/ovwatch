# ovwatch 暑期实习作品框架

## 1. 当前项目定位

这是一个基于 STM32F411 的智能手表原型项目，已经具备作品集价值：

- 屏幕：ST7789，已有初始化、刷屏、文字、线条、矩形、RTC 时间显示。
- 触摸：CST816T，已有 I2C 读取、坐标映射、点击/上下左右滑动识别。
- 传感器：MPU6050 已有加速度、陀螺仪读取，并实现摇动唤醒逻辑。
- 健康模块：MAX30102 文件已创建，但驱动和算法还没展开。
- 产品行为：已有主页、菜单、画板、触摸测试、MPU6050 页面、息屏/唤醒。

目前最适合包装的方向是：**一个从裸机原型逐步升级到 FreeRTOS + LVGL 的智能手表小系统**。这比单纯做几个页面更容易打动嵌入式实习面试官。

## 2. 面试官真正想看到什么

面试官不是只看“界面好不好看”，而是看你有没有工程能力：

- 能不能读芯片手册并写出可维护的驱动。
- 能不能解释 SPI、I2C、EXTI、RTC、DMA、中断、定时器的取舍。
- 能不能把主循环拆成任务，理解 FreeRTOS 的任务、队列、互斥锁和优先级。
- 能不能把 LVGL 移植到自己的屏幕和触摸上，而不是只用 SquareLine 拖界面。
- 能不能做出稳定可演示的功能，并用文档、视频、Git 提交记录讲清楚。

你的项目应该被讲成一句话：

> 我做了一个 STM32 智能手表原型，完成 ST7789 显示、CST816T 触摸、MPU6050 姿态检测、MAX30102 健康采集，并正在将裸机事件循环升级为 FreeRTOS + LVGL 架构。

## 3. 推荐总体架构

建议把项目拆成 4 层，后面写 README 和简历都按这个讲：

```text
Application
  watch_app.c        页面状态机、业务逻辑、低功耗策略
  health_app.c       心率/血氧采集状态机
  motion_app.c       抬腕/摇动检测、步数或姿态判断

UI
  lv_port_disp.c     LVGL 显示 flush，对接 ST7789
  lv_port_indev.c    LVGL 输入 read，对接 CST816T
  ui_screen_xxx.c    SquareLine 导出的页面和事件回调

Service / Driver
  bsp_lcd_st7789.c   SPI 屏幕驱动，后续支持 DMA
  bsp_touch_cst816.c I2C 触摸驱动，中断触发
  bsp_mpu6050.c      姿态传感器驱动
  bsp_max30102.c     心率血氧传感器驱动
  bsp_rtc.c          时间服务

Platform
  STM32 HAL
  FreeRTOS
  CMSIS
```

当前代码可以先保留，下一阶段不要急着全量重构。优先做“并行新架构”，比如新建 `bsp_` 和 `app_` 文件逐步迁移。

## 4. 三阶段路线图

### 阶段 A：两周内做成可演示裸机版本

目标：先拿到一个稳定 demo，能录视频、能放 GitHub/Gitee。

- 修正并确认 Keil 0 error / 0 warning。
- 给 `ui.h` 补齐 `UI_ScreenOn`、`UI_ScreenOff`、`UI_ActiveUpdate` 原型。
- 给 README 写清楚硬件清单、引脚表、功能列表、构建方法。
- 完成 MAX30102 最小驱动：读 ID、配置寄存器、读取 FIFO 原始红光/红外数据。
- 健康页先显示原始 IR/RED 波形或数值，不急着追求医学准确心率血氧。
- 录一个 30-60 秒演示视频：开机、滑动菜单、画板、触摸测试、MPU6050 数据、摇动唤醒。

阶段 A 完成后，你就有“可投递”的作品雏形了。

### 阶段 B：四周内升级为 FreeRTOS 工程

目标：让项目从“功能堆起来”变成“系统设计”。

推荐任务划分：

```text
UiTask          20-33 ms 调用 LVGL handler / 或当前 UI 刷新
TouchTask       等待触摸中断信号，读取坐标，发送事件到队列
MotionTask      50-100 ms 读取 MPU6050，判断抬腕/摇动
HealthTask      采集 MAX30102 FIFO，做滤波和心率估计
PowerTask       管理息屏、唤醒、低功耗入口
LogTask         串口输出调试信息
```

你要重点掌握并能讲清楚：

- 为什么触摸中断里只置标志/发信号，不在中断里做 I2C 大量读取。
- 为什么 UI 绘制需要单线程或加互斥锁，避免多个任务同时刷屏。
- 为什么传感器采样和 UI 刷新要解耦，使用队列传递数据。
- 每个任务的栈大小、优先级、周期怎么估算。
- 如何通过串口打印任务运行状态、剩余栈、错误码。

### 阶段 C：六到八周内完成 LVGL + SquareLine 作品版

目标：让界面、架构、文档都达到实习作品标准。

- 移植 LVGL 显示：实现 `flush_cb`，先阻塞 SPI，后续再优化 DMA。
- 移植 LVGL 触摸：实现 `read_cb`，把 CST816T 坐标变成 LVGL 输入事件。
- SquareLine 负责页面布局，手写代码负责传感器数据绑定和事件逻辑。
- 加 4 个核心页面：表盘、健康、运动/姿态、设置。
- 设置页至少支持亮度/息屏时间/传感器开关其中 1-2 项。
- 加性能记录：刷新帧率、CPU 占用、RAM/Flash 占用、一次全屏刷新耗时。

## 5. 最值得做的功能优先级

优先级 1：必须完成

- ST7789 显示稳定。
- CST816T 点击和滑动稳定。
- RTC 时间显示。
- 息屏、触摸唤醒、摇动唤醒。
- README、引脚表、演示视频。

优先级 2：很加分

- FreeRTOS 任务拆分。
- LVGL 移植到真屏幕和真触摸。
- MAX30102 FIFO 原始数据读取和波形显示。
- MPU6050 简单动作识别，例如抬腕/摇动/静止。
- 串口日志和错误码。

优先级 3：锦上添花

- SPI DMA 刷屏。
- 局部刷新优化。
- 心率算法滤波和峰值检测。
- 低功耗模式。
- PC 端 LVGL 模拟器。

## 7. 面试时要准备的 12 个问题

- ST7789 是怎么初始化的？为什么要设置 `CASET`、`RASET`、`RAMWR`？
- SPI 刷全屏为什么慢？如何用 DMA 或局部刷新优化？
- CST816T 的触摸坐标为什么需要映射？
- 为什么中断回调里不直接刷新 UI？
- FreeRTOS 里 UI 任务和传感器任务如何通信？
- 多任务同时访问屏幕会发生什么？怎么解决？
- LVGL 移植需要哪些接口？
- `lv_tick` 和 `lv_timer_handler` 分别负责什么？
- MAX30102 的 FIFO 是什么？为什么不能只读一个寄存器？
- MPU6050 原始值如何换算成 g 和 deg/s？
- 低功耗时哪些外设要关闭？哪些中断可以唤醒？
- 你遇到过最难的 bug 是什么，怎么定位的？

## 8. 每周执行计划

第 1 周：

- 确认工程 0 error / 0 warning。
- 整理 README、硬件引脚表、项目结构图。
- 录制当前裸机版本演示视频。

第 2 周：

- 完成 MAX30102 读 ID、初始化、FIFO 读取。
- 健康页显示 RED/IR 原始数据。
- 用串口打印传感器采样数据。

第 3-4 周：

- CubeMX 开启 FreeRTOS。
- 拆出 TouchTask、MotionTask、UiTask。
- 用队列/事件标志传递触摸和传感器事件。

第 5-6 周：

- 移植 LVGL 显示和触摸。
- 接入 SquareLine 页面。
- 做表盘、菜单、健康、姿态、设置页面。

第 7-8 周：

- 优化刷新和功耗。
- 补充文档、架构图、演示视频、关键代码讲解。
- 开始集中投递嵌入式软件、单片机、IoT、智能硬件相关实习。
